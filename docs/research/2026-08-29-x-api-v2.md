# Research: X API v2 — pay-per-use, bookmarks endpoint, OAuth 2.0
Date: 2026-08-29 | Source: research subagent, docs.x.com + devcommunity threads (fetched 2026-08-29)

## Verified
**Pricing / pay-per-use** — https://docs.x.com/x-api/getting-started/pricing
- Pay-per-usage, "no contracts, subscriptions, or minimum spend." Credits purchased upfront in the Developer Console (https://console.x.com). Auto-recharge optional (needs saved card). Per-cycle spending limit configurable. Balance may go slightly negative, then requests block.
- Reads charged **per resource returned**; Posts $0.005/resource, Users $0.010/resource.
- **Owned Reads: $0.001/resource** for 12 endpoints incl. `GET /2/users/{id}/bookmarks` when `{id}` is the authenticated user who owns the app. Rollout was "progressive" as of 2026-04-20 (https://devcommunity.x.com/t/263311) — budget at $0.005 worst case.
- **Dedup: resources deduplicated within a 24-hour UTC window** (soft guarantee). Cap 3M post reads/cycle.
- Legacy tiers: Basic auto-migrated to PPU after 2026-06-01 (https://devcommunity.x.com/t/266305), Pro after 2026-09-01 (https://devcommunity.x.com/t/273255). New signups: PPU only.

**Bookmarks endpoint** — https://docs.x.com/x-api/users/get-bookmarks
- `GET https://api.x.com/2/users/{id}/bookmarks`; scopes `bookmark.read`, `users.read`, `tweet.read`.
- `max_results` 1–100, `pagination_token`. `expansions`: `attachments.media_keys`, `author_id`, `referenced_posts`, `attachments.media_source_tweet`. `media.fields`: `duration_ms, media_key, preview_image_url, type, url, variants, width, height`. Field param is `post.fields` in the reference (`tweet.fields` still in quickstart).
- Media object (https://docs.x.com/x-api/fundamentals/data-dictionary): `type` ∈ `animated_gif | photo | video`; `variants[] = {bit_rate, content_type: "video/mp4", url: "https://video.twimg.com/…mp4?tag=12"}`; `preview_image_url`.
- Rate limits (https://docs.x.com/x-api/fundamentals/rate-limits): bookmarks **180 req/15 min per user**; `GET /2/users/me` 75/15 min.
- Pagination bug: `next_token` stops after 2–3 pages at `max_results=100`; workaround: `max_results` ≤ 90 (https://devcommunity.x.com/t/257339).

**OAuth 2.0** — https://docs.x.com/fundamentals/authentication/oauth-2-0/authorization-code , https://docs.x.com/fundamentals/developer-apps
- Authorize `https://x.com/i/oauth2/authorize`; token `https://api.x.com/2/oauth2/token`; revoke `/2/oauth2/revoke`. PKCE (S256) required.
- App type "Web App, Automated App or Bot" = confidential client with Client Secret. Callback URL required, exact match, ≤10 per app.
- Confidential client: `Authorization: Basic base64(client_id:client_secret)` on the token endpoint.
- Access token lives **2 hours**; refresh tokens only with `offline.access`.
- **Refresh tokens rotate and are single-use**; the old one is invalidated server-side immediately, even if the client never receives the response. Keep the previous token briefly as fallback (https://devcommunity.x.com/t/271768).

**users/me** — https://docs.x.com/x-api/users/get-my-user — `GET /2/users/me`, scopes `tweet.read users.read`; works under PPU per staff (https://devcommunity.x.com/t/274282). Call once, cache the id.

**video.twimg.com** — anonymous HEAD returns `accept-ranges: bytes`, exposes `Content-Length`, `cache-control: max-age=3600`; no signing seen (`?tag=NN` only).

## Unverified / conflicting
- Whether $0.001 Owned Reads is applied to bookmarks yet (budget $0.005).
- Whether `includes.users` (via `author_id`) bills as a $0.010 user read; whether `includes.media` bills. **Avoid `author_id`/`user.fields`.**
- Refresh-token idle expiry (~6 months claimed by community; not in docs).
- Whether `animated_gif` returns mp4 `variants` (docs silent; `duration_ms` is video-only).
- 800-most-recent cap: historically staff-confirmed (https://devcommunity.x.com/t/169433), not in current docs.
- Whether `attachments.media_source_tweet` surfaces quoted-post video without a second lookup.
- One 2026-08 thread reports account-level 403 on `/users/me` under PPU, unresolved (https://devcommunity.x.com/t/274282).

## Cost estimate (48 polls/day × 20 results, ~3 new bookmarks/day)
Dedup ⇒ ~20 repeated + 3 new = ~23 resources/day.
- Owned Reads: **≈ $0.02/day ≈ $0.70/month**.
- Standard rate: ≈ $0.12/day ≈ $3.50/month.
- Dedup failure worst case: 960 × $0.005 = $4.80/day → **set a spending limit**.

## Design implications
- Cost depends on returned posts/day, not polling frequency; 30-min polling is fine. `max_results` ≤ 90.
- Refresh proactively before the 2 h expiry; persist the new refresh token before using it; keep previous as fallback; on double failure require re-auth via a route.
- Request `expansions=attachments.media_keys&media.fields=media_key,type,variants,preview_image_url,duration_ms&tweet.fields=created_at,text,attachments`; pick highest `bit_rate` `video/mp4` variant. Skip `author_id`.
- Quoted-post video: not in v1 (would need `referenced_posts` + extra lookup at $0.005).
